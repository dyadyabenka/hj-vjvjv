# RSS → LLM → модерация в личке → Telegram-канал

Бот работает **непрерывно** (не по расписанию cron): раз в `run.interval_hours`
сам собирает свежие статьи из RSS, группирует по темам, готовит из каждой
группы черновик поста и присылает его тебе в личку с двумя кнопками:

- **✅ Опубликовать** — пост уходит в канал как есть
- **✏️ Доработать** — бот спросит, что поправить, ты пишешь текстом
  ("сделай короче", "убери про Х", "смести акцент на Y" и т.п.), бот
  переписывает пост и присылает новый вариант с теми же двумя кнопками.
  Можно повторять сколько угодно раз, пока не устроит.

Ничего не публикуется в канал без твоего явного нажатия "Опубликовать".

## Как это работает

```
каждые N часов:
  fetcher.py      собирает статьи из RSS, отбрасывает старые
       ↓
  storage.py      отсеивает дубли, пишет в SQLite
       ↓
  fetcher.py      фильтрует по ключевым словам темы (fetch.keywords)
       ↓
  clusterer.py    склеивает статьи об одном исследовании/событии
       ↓
  synthesizer.py  пишет пост через LLM (Claude или DeepSeek)
       ↓
  images.py       подбирает реальное фото по теме (Pexels)
       ↓
  storage.py      сохраняет черновик как pending_review
       ↓
  publisher.py    присылает черновик тебе в личку с кнопками

когда ты нажимаешь кнопку:
  "Опубликовать"  → publisher.py публикует в канал, storage.py помечает пост published
  "Доработать"    → бот просит замечание текстом → synthesizer.revise() переписывает
                     пост → publisher.py присылает новый черновик с кнопками снова
```

Файлы:

| Файл | Назначение |
|---|---|
| `main.py` | точка входа: непрерывный режим (Application + JobQueue) и `--dry-run` |
| `fetcher.py` | сбор статей из RSS + фильтр по ключевым словам темы |
| `storage.py` | SQLite: статьи и черновики постов на модерации |
| `clusterer.py` | группировка похожих статей (`scikit-learn`) |
| `synthesizer.py` | синтез (`synthesize`) и доработка по замечаниям (`revise`) через LLM |
| `images.py` | подбор фото по теме через Pexels API |
| `publisher.py` | отправка черновиков на модерацию и публикация в канал |
| `config.yaml` | источники, тема канала, расписание, картинки |
| `.env` | секреты (создаётся из `.env.example`) |

## Установка

```bash
python -m venv venv
```

Linux/macOS: `source venv/bin/activate`
Windows (PowerShell): `venv\Scripts\Activate.ps1`

```bash
pip install -r requirements.txt
```

## Настройка

1. Скопируй `.env.example` в `.env`:

   ```bash
   cp .env.example .env
   ```

2. Заполни в `.env`:

   * ключ LLM — только один из двух, тот, что указан как `provider` в `config.yaml`:
     * `DEEPSEEK_API_KEY` — [platform.deepseek.com](https://platform.deepseek.com) → API Keys → Create Key. Новый аккаунт получает бесплатный грант токенов.
     * `ANTHROPIC_API_KEY` — [console.anthropic.com](https://console.anthropic.com/settings/keys)
   * `TELEGRAM_BOT_TOKEN` — токен от [@BotFather](https://t.me/BotFather)
   * `TELEGRAM_CHANNEL_ID` — `@username` канала либо числовой id вида `-1001234567890`
   * `TELEGRAM_ADMIN_ID` — твой личный chat id. Узнать: напиши боту **@userinfobot**, он ответит числом.
     **Важно**: перед первым запуском сам напиши что-нибудь своему боту (хотя бы `/start`) —
     иначе Telegram не разрешит боту написать тебе первым.
   * `PEXELS_API_KEY` — необязательно. Получить бесплатно на [pexels.com/api](https://www.pexels.com/api/) →
     Get Started, ключ выдаётся сразу. Без него посты идут без картинок.

3. **Добавь бота администратором канала** с правом публикации сообщений.

4. Открой `config.yaml`: тема, RSS-источники и `fetch.keywords` уже настроены под
   тему паразитологии/микробиома — поменяй под себя, если нужно.

## Запуск

Проверка настроек без Telegram (один проход конвейера, черновики печатаются в лог):

```bash
python main.py --dry-run
```

Боевой запуск — бот работает, пока не остановишь (Ctrl+C):

```bash
python main.py
```

Раз в `run.interval_hours` бот сам прогонит конвейер и пришлёт тебе черновики в
личку. Никакого cron не нужно — процесс должен просто оставаться запущенным.

## Как оставить бота работающим постоянно

Это уже не разовый скрипт для cron, а процесс, который должен работать не
останавливаясь. Варианты:

**Проще всего для теста** — оставить открытым терминал с `python main.py`.

**Windows, чтобы работало в фоне и после закрытия терминала:**
```bash
pythonw main.py
```
(`pythonw` — без консольного окна; вместо `pythonw` можно использовать
Планировщик заданий с триггером "при запуске системы" вместо расписания по часам)

**Linux/macOS, через systemd** — создай юнит с `Restart=always`, чтобы бот
автоматически перезапускался при сбое. Либо проще: `screen`/`tmux` сессия с
запущенным `python main.py` внутри.

## Модерация: как это выглядит

1. Бот присылает тебе в личку фото (если нашлось) + текст поста + две кнопки.
2. Жмёшь **✅ Опубликовать** — пост сразу уходит в канал.
3. Жмёшь **✏️ Доработать** — бот пишет "Напиши, что поправить" — отвечаешь
   обычным текстовым сообщением (например: "сократи вдвое", "добавь про
   лактобактерии подробнее", "смести акцент на детей") — бот присылает
   переписанный вариант с теми же кнопками. Можно повторять.

Ограничение: `revise()` переписывает пост на основе **тех же исходных статей**,
что и черновик — бот не выдумывает факты, которых не было в источниках.
Если попросить "напиши про другое" в отрыве от исходных статей, модель
постарается, но качество будет хуже — для реально другой темы проще
дождаться следующего планового прогона.

## Про провайдера и модель

`synthesis.provider` в `config.yaml`:

* `deepseek` (по умолчанию) — дёшево, есть бесплатный стартовый грант токенов.
  Модели: `deepseek-v4-flash` (быстро и дёшево) или `deepseek-v4-pro` (умнее, дороже).
* `anthropic` — модели: `claude-sonnet-4-6` (баланс), `claude-opus-5` (умнее,
  дороже), `claude-haiku-4-5` (быстрее и дешевле).

DeepSeek отдаёт Anthropic-совместимый эндпоинт (`api.deepseek.com/anthropic`),
поэтому переключение — это смена `provider`/`model` в `config.yaml` и
соответствующего ключа в `.env`. Код `synthesizer.py` для обоих провайдеров общий.

## Про фильтр по ключевым словам

Источники в `config.yaml` — общенаучные издания (охватывают всё, не только
паразитологию). `fetch.keywords` — список слов, хотя бы одно из которых
должно встретиться в заголовке или описании статьи, иначе она отбрасывается
ещё на этапе сбора. Пустой список — фильтр выключен (берётся всё).

## Про картинки

`images.py` подбирает англоязычный поисковый запрос под тему статьи (например,
"пробиотик" → `probiotics yogurt bacteria`) и ищет фото через Pexels API.
Если `PEXELS_API_KEY` не задан или Pexels не нашёл фото — пост уходит без
картинки, это не считается ошибкой.

## Про кластеризацию

TF-IDF считается по **символьным** n-граммам (3–5 символов), а не по словам —
для русского это работает лучше: «Яндекс купил» и «покупка Яндексом» дают
общие символьные n-граммы, а как отдельные слова не совпадают вовсе.

Несвязанные заголовки дают сходство 0.00–0.05, статьи об одном событии —
0.25–0.55. Если статьи склеиваются слишком охотно — подними
`clustering.similarity_threshold` до 0.30–0.35, если всё разваливается на
одиночные посты — опусти до 0.20.

## База данных

`articles.db`, таблицы:

* `articles` — все увиденные статьи, статус `new` / `processed` / `published`
* `posts` — черновики постов на модерации, статус `pending_review` / `published`,
  хранит текст статей-источников (`articles_block`) для доработки

Начать с чистого листа — удалить `articles.db`, база пересоздастся сама.

```bash
sqlite3 articles.db "SELECT status, COUNT(*) FROM posts GROUP BY status;"
```

## Типичные проблемы

| Симптом | Причина |
|---|---|
| `Не заполнены переменные окружения` | нет `.env` или пустые значения |
| Бот не пишет тебе в личку черновики | ты не написал боту первым (`/start`) — Telegram блокирует первое сообщение от бота |
| Telegram отклонил сообщение (400) `chat not found` | неверный `TELEGRAM_CHANNEL_ID`/`TELEGRAM_ADMIN_ID`, либо бот не в администраторах канала |
| `Неверный DEEPSEEK_API_KEY` / `ANTHROPIC_API_KEY` | опечатка или ключ отозван |
| Посты без картинок | `PEXELS_API_KEY` не задан, или Pexels не нашёл фото — не ошибка |
| Один и тот же сюжет двумя постами | подними `clustering.similarity_threshold` |
| Кнопки под старым черновиком перестали работать после "Доработать" | так и задумано — старая разметка снимается, новый черновик приходит отдельным сообщением с новыми кнопками |
