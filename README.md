# RSS → LLM → модерация в личке → несколько Telegram-каналов

Один бот ведёт сразу несколько каналов: паразитология/микробиом, сон,
питание, крипта — список задаётся в `config.yaml` (`channels:`), можно
добавлять и убирать каналы без переписывания кода.

Бот работает **непрерывно** (не по cron): раз в `run.interval_hours`
проходит по всем каналам по очереди, готовит черновики и присылает их тебе
в личку с пометкой, к какому каналу относится каждый, и тремя кнопками:

- **✅ Опубликовать** — пост уходит в тот канал, что указан в черновике
- **✏️ Доработать** — бот спросит, что поправить, ты пишешь текстом,
  бот переписывает пост и присылает новый вариант с теми же кнопками.
  Можно повторять сколько угодно раз.
- **❌ Отменить** — черновик отбрасывается насовсем, статьи-источники этой
  темы больше не предлагаются повторно (помечаются как обработанные)

Ничего не публикуется без твоего явного нажатия "Опубликовать".

## Как это работает

```
каждые N часов, по каждому каналу из config.yaml по очереди:
  fetcher.py      собирает статьи из СВОИХ RSS канала (общие ленты
                   скачиваются один раз на все каналы, не дублируются)
       ↓
  storage.py      отсеивает дубли (общая таблица статей на все каналы)
       ↓
  fetcher.py      фильтрует по ключевым словам ЭТОГО канала
       ↓
  clusterer.py    склеивает статьи об одном событии/исследовании
       ↓
  synthesizer.py  пишет пост через LLM с темой ЭТОГО канала
       ↓
  images.py       подбирает фото (запрос — свой для темы канала)
       ↓
  storage.py      сохраняет черновик как pending_review с channel_id
       ↓
  publisher.py    присылает черновик в личку с пометкой "Канал: ..." и кнопками

когда ты нажимаешь кнопку:
  "Опубликовать"  → publisher.py публикует в ТОТ канал, что в черновике
  "Доработать"    → synthesizer.revise() переписывает с темой того же канала
```

Файлы:

| Файл | Назначение |
|---|---|
| `main.py` | точка входа: непрерывный режим (Application + JobQueue) и `--dry-run`, обходит все каналы |
| `fetcher.py` | сбор статей из RSS для одного канала + фильтр по его ключевым словам |
| `storage.py` | SQLite: статьи (общие) и черновики постов (с полем channel_id) |
| `clusterer.py` | группировка похожих статей (`scikit-learn`) |
| `synthesizer.py` | синтез (`synthesize`) и доработка (`revise`) через LLM — тема передаётся аргументом |
| `images.py` | подбор фото по теме через Pexels API |
| `publisher.py` | отправка черновиков на модерацию (с пометкой канала) и публикация |
| `config.yaml` | список каналов, источники и ключевые слова каждого, расписание |
| `.env` | секреты, включая свой TELEGRAM_CHANNEL_ID_* на каждый канал |

## Установка

```bash

```

Linux/macOS: `source venv/bin/activate`
Windows (PowerShell): `venv\Scripts\Activate.ps1`

```bash
pip install -r requirements.txt
```

## Настройка

1. Скопируй `.env.example` в `.env`:

   ```bash
   cp .env.example .env
   ```

2. Заполни в `.env`:

   * ключ LLM — только один из двух, тот, что указан как `provider` в `config.yaml`
   * `TELEGRAM_BOT_TOKEN` — токен от [@BotFather](https://t.me/BotFather) (один бот на все каналы)
   * `TELEGRAM_ADMIN_ID` — твой личный chat id (узнать через **@userinfobot**).
     **Важно**: сам напиши боту `/start` перед первым запуском.
   * **По одной переменной `TELEGRAM_CHANNEL_ID_*` на каждый канал** —
     имена уже заданы под 4 канала из коробки (`_PARASITES`, `_SLEEP`,
     `_NUTRITION`, `_CRYPTO`). Если добавишь свой канал в `config.yaml`,
     заведи под него новую переменную и укажи её имя в `channel_id_env`.
   * `PEXELS_API_KEY` — необязательно, без него посты идут без картинок

3. **Добавь бота администратором в КАЖДЫЙ из каналов** с правом публикации.

4. Открой `config.yaml` → `channels:` — у каждого канала своя тема,
   источники и ключевые слова. Добавить новый канал — скопировать один
   блок в списке и поменять `id`, `name`, `channel_id_env`, `topic`,
   `keywords`, `sources`.

## Запуск

Проверка без Telegram (один проход по всем каналам, черновики в лог):

```bash
python main.py --dry-run
```

Боевой запуск — работает, пока не остановишь (Ctrl+C):

```bash
python main.py
```

## Как добавить ещё один канал

1. В `config.yaml` в `channels:` добавь новый блок по образцу существующих
2. Придумай новое имя переменной для `channel_id_env`, например `TELEGRAM_CHANNEL_ID_SPORT`
3. Добавь эту переменную в `.env` со значением канала
4. Добавь бота администратором в новый канал
5. Перезапусти бота

Код трогать не нужно — вся конфигурация каналов живёт в `config.yaml`.

## Модерация: как это выглядит

Бот присылает в личку фото (если нашлось) + строку **"📌 Канал: ..."** +
текст поста + три кнопки. Жмёшь "Опубликовать" — уходит именно в этот канал.
Жмёшь "Доработать" — пишешь замечание текстом, бот переписывает пост с той же
темой (той же, что у канала черновика) и присылает заново. Жмёшь "Отменить" —
черновик просто исчезает, ничего никуда не публикуется.

Ограничение: `revise()` переписывает пост на основе тех же исходных статей,
что и черновик — бот не выдумывает факты, которых не было в источниках.

## Автоматическая модерация (moderation в config.yaml)

Перед тем как черновик уходит тебе в личку, бот делает две дополнительные
проверки — они не заменяют твою модерацию, ничего не публикуется без
"Опубликовать" в любом случае:

1. **Критическая самопроверка** (`fact_check_enabled: true`) — второй запрос
   к той же модели: "вот пост, вот исходные статьи, найди выдуманные факты,
   противоречия, натянутые обобщения". Если находит проблему — пост всё
   равно приходит тебе, но с пометкой `⚠️ Проверка: ...` в начале сообщения.
   Это не гарантия правды (см. разговор про актуальность выше), а
   дополнительный взгляд "со стороны" на очевидные нестыковки.
2. **Проверка на повтор темы** — новый черновик сравнивается с постами,
   которые уже ОПУБЛИКОВАНЫ в этом канале за последние
   `duplicate_check_days` дней (по умолчанию 30). Если похоже — черновик
   тебе просто не присылается, статьи-источники помечаются обработанными.

Настройки — секция `moderation` в `config.yaml`:
`fact_check_enabled`, `duplicate_check_days`, `duplicate_similarity_threshold`
(0..1, выше — сложнее счесть посты дубликатами).

## Команда /pending

Если кнопки под черновиком в Telegram пропали (сообщение потерялось, или
публикация не удалась и нужно повторить) — напиши боту `/pending`, он заново
пришлёт все черновики, которые ещё ждут решения (не опубликованы и не
отменены), с рабочими кнопками.

## Про источники и пересечение каналов

Статьи хранятся в одной общей таблице (по `url`) — если разные каналы
используют одну и ту же RSS-ленту (так сделано для "сон"/"питание"/
"паразитология" — все три берут N+1, Naked Science и т.д.), лента
скачивается один раз за прогон, а не по разу на канал.

Чтобы статья не "утекла" не в свой канал, ключевые слова проверяются дважды:
один раз сразу после скачивания, и ещё раз при выборке "необработанных"
статей из базы (`storage.load_pending(..., keywords=...)`) — так материал,
не попавший в пост в свой первый прогон, в следующий раз всё равно
достанется только правильному каналу, а не первому, кто до него доберётся.

## Примеры постов (style_examples) — через бота или через config.yaml

Два способа задать примеры стиля, работают вместе:

**Через бота (проще, без деплоя):**
- `/example <id_канала>` — бот попросит прислать текст примера следующим
  сообщением, сохранит его в базу
- `/examples` — покажет, сколько примеров сохранено на каждый канал
- `/clear_examples <id_канала>` — удалит примеры этого канала, сохранённые
  через бота (то, что прописано в `config.yaml`, не трогает)

Id каналов — те, что в `config.yaml` (`parasites`, `sleep`, `nutrition`,
`crypto` из коробки), бот подскажет список, если ошибёшься в названии.

**Через config.yaml (нужен передеплой):** поле `style_examples` у каждого
канала — см. синтаксис ниже.

Если примеры заданы и через бота, и в конфиге — используются оба набора
вместе. Если нет ни одного — модель ориентируется только на текстовые
правила в промпте, как раньше (жёсткого лимита по словам больше нет, но без
примеров модель сама решает, каким получится объём).

Синтаксис YAML для многострочного текста — символ `|` после дефиса:

```yaml
style_examples:
  - |
    🦠 Заголовок первого примера

    Текст примера как он есть, с переносами строк,
    ровно в том виде, в каком пост обычно выглядит у тебя в канале.
```

1-2 примера уже дают заметный эффект, 3 обычно достаточно — больше не даёт
прироста, только удлиняет промпт.

## Про провайдера и модель

`synthesis.provider` в `config.yaml` — один на все каналы:

* `deepseek` (по умолчанию) — дёшево, есть бесплатный стартовый грант токенов
* `anthropic` — `claude-sonnet-4-6` / `claude-opus-5` / `claude-haiku-4-5`

## Про картинки

Каждый канал ищет фото по-своему: если заголовок статьи совпал с одним из
ключевых слов в `images.py` (`_KEYWORD_TO_QUERY`) — используется точный
англоязычный запрос под тему; если нет — берётся случайный запрос из
`fallback_image_queries` этого канала в `config.yaml`.

Картинки не повторяются: перед выбором бот смотрит все уже использованные
фото (по всем каналам сразу — `storage.get_used_image_urls()`) и просит у
Pexels 20 вариантов, отбирая первый неиспользованный.

## Про ссылки на источники

Пост не содержит ссылок, названий изданий и блока "Источники" — промпт прямо
просит писать как самостоятельный авторский текст. Ссылки на статьи-источники
остаются в базе (`posts.article_urls`, `articles_block`) для дедупликации и
доработки, наружу не публикуются.

## База данных

`articles.db`, таблицы:

* `articles` — все увиденные статьи (общие для всех каналов), статус
  `new` / `processed` / `published`
* `posts` — черновики постов, включая `channel_id`, статус
  `pending_review` / `published`

```bash
sqlite3 articles.db "SELECT channel_id, status, COUNT(*) FROM posts GROUP BY channel_id, status;"
```

## Типичные проблемы

| Симптом | Причина |
|---|---|
| `Не заполнены переменные окружения: TELEGRAM_CHANNEL_ID_SPORT` | добавил канал в config.yaml, но забыл соответствующую переменную в `.env` |
| Бот не пишет тебе черновики | ты не написал боту первым (`/start`) |
| `chat not found` при публикации | неверный `TELEGRAM_CHANNEL_ID_*`, либо бот не админ этого конкретного канала |
| Черновики приходят не по той теме | пересекающиеся ключевые слова у двух каналов — сузь `keywords` |
| Посты без картинок | `PEXELS_API_KEY` не задан, или Pexels не нашёл фото — не ошибка |
